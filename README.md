# RallyCut

Windows 优先的本地羽毛球视频标局工具。Tauri 2 + React/TypeScript + Rust + SQLite + 原生 FFmpeg。

当前是可以运行的首版：导入多个视频，建立统一时间线，标记每局，全局区间自动映射到一个或多个源文件，直接输出一局完整视频。不会先将全部素材转码，也不上传任何素材。

## 下载与安装

前往 [GitHub Releases](https://github.com/Hessel2333/RallyCut/releases/latest) 下载 Windows x64 的 `RallyCut_*_x64-setup.exe` 并安装。视频处理需要 FFmpeg 和 ffprobe，在应用设置中选择本机可执行文件即可。

应用提供“版本与更新”入口：默认自动检查并下载，点击确认后安装；也可关闭自动更新并手动检查。更新完成后首次打开会弹窗显示更新细节。

## 开发启动

需要 Node.js 22、Rust stable/MSVC、Visual Studio C++ Build Tools、Windows WebView2，以及可选的本机 FFmpeg/ffprobe。工具缺失不会阻止打开应用。

```powershell
npm ci
npm run tauri dev
```

开发机本次使用已有的 FFmpeg 7.0.1，没有下载视频工具。可仅为当前 PowerShell 会话指定工具目录：

```powershell
$env:RALLYCUT_FFMPEG_DIR='C:/Program Files/ffmpeg-7.0.1-full_build/bin'
npm run tauri dev
```

生产构建（安装包及更新签名配置见 [发布说明](docs/RELEASING.md)）：

```powershell
npm run tauri build -- --bundles nsis -- --locked
```

安装包位于 `src-tauri/target/release/bundle/nsis/`。`npm run dev` 仅启动网页开发服务；桌面开发请运行 `npm run tauri dev`。

## 使用

1. 在设置中检查 FFmpeg/ffprobe；需要时分别选择两个可执行文件，并设置素材库、输出目录。
2. 导入素材 → 选择目录 → 自然排序扫描 → 上下调整次序 → 就地引用或复制导入 → 建立拍摄记录。扫描当前目录，不递归搜索磁盘。文件相邻不代表拍摄连续。
3. 播放、点击时间线或跳转定位。`I` / `O` 设置边界，`Enter` 添加一局；也可输入 `时:分:秒.毫秒`，拖动时间线下方起止手柄。右侧可改名、调整时间、填写比分备注、删除标记。
4. `Space` 播放暂停；方向键 ±1 秒，Shift+方向键 ±10 秒；Ctrl+Z / Ctrl+Shift+Z 撤销重做标记。输入框编辑时不触发剪辑快捷键。WebView 播放不承诺逐帧精确。
5. 选择比赛并导出。输出名称预览来自后端，重名追加编号；每次一个转码任务，可取消、重试、暂停启动后续任务。编辑标记不会改动已经入队的快照。
6. 无法流畅预览时，可为当前文件生成 H.264 代理或单张缩略图。均按需生成、可取消并缓存；最终导出只使用原片。代理保留原片时长与零偏移映射，生成后检查时长。

### 连续分段、标签与导出设置

- 到每局结束位置按 **S / 在此分段**，生成上一终点到当前位置的一局，并自动接续下一段起点。在已有比赛内部按 S 会拆成两段。I 可跳过局间休息；I/O/Enter 仍可用，添加后同样接续终点。新增和边界修改拒绝与其他比赛重叠，旧标记不自动改变。
- 下一段标签及每局列表提供男单、男双、混双、男双vs混双、拉练等快捷按钮，也可输入自定义名称。
- 新任务输出为 `输出目录/拍摄日期/1-男单.mp4`。同日跨拍摄记录编号，优先用首素材的拍摄时间加统一时间线位置排序；缺少时间的记录排在其后，按导入顺序和局内位置排列。编号包含未勾选比赛，避免只导出部分时重新从 1 开始。增删较早比赛会改变后续新任务编号；历史任务和文件保持原名，重名继续追加后缀。
- 顶部 **导出设置** 随时可打开，内置 B站 4K、1080p 60fps，可另存或更新命名预设。支持分辨率、视频/音频码率、跟随源帧率或强制 60fps、编码器；当前参数与预设存入 SQLite。输出目录在此选择，立即生效于后续任务。
- 任务队列默认只显示当前拍摄，可切到全部任务。每条记录显示当时的分辨率、帧率策略、码率。暂停队列仍作用于全部拍摄的后续任务。
- 应用设置保留工具路径、素材库与硬件检测。预览缓存仍使用应用数据目录，尚无缓存空间管理界面。
- 左侧每条拍摄记录右侧的垃圾桶可删除记录，确认后只移除该拍摄及比赛标记，素材文件、素材索引和历史导出均保留；历史任务可在“全部任务”查看。存在排队或执行中的任务时禁止删除。删除后其他比赛的新导出编号会重新排列，已有输出不改名。

默认预设：MP4/H.264、3840×2160、目标平均 20,000kbps、AAC 192kbps、原片第一段的真实分数帧率，也可强制 60fps。保持比例补边，启用 faststart。这不是 HandBrake 预设的完整复现。多音轨采用第一条；无音频或音频较短会按视频区间补静音。

明确的 HDR/BT.2020 素材拒绝导出；不完整的色彩标签必须由使用者确认普通 SDR、非 D-Log。不能仅靠 ffprobe 确认所有未标记的 Log 素材。原片色彩信息位于设置的媒体信息折叠区。

## 工具、数据与文件安全

- 检测顺序：显式配置路径；未配置时检查应用数据目录的 `tools/ffmpeg.exe` / `tools/ffprobe.exe`、开发环境变量 `RALLYCUT_FFMPEG_DIR`、PATH。验证执行结果并显示版本。不会自动下载。
- 在首次导出或设置中用短视频实测 NVENC/QSV/AMF。自动模式优先采用实测通过的编码器，硬件导出失败后回退 CPU，并保留失败原因。
- SQLite、默认素材库和缓存位于 `%APPDATA%/local.rallycut.desktop/`：`rallycut.sqlite3`、`library/`、`cache/`。采用 WAL 与版本迁移；备份时应关闭应用，或同时保留 WAL。
- 默认输出目录是 Windows 视频目录下的 `RallyCut/`；可在设置中更换。
- 复制使用 1MiB 缓冲、源 SHA-256 和目标读回 SHA-256；验证后才正式提交。已索引并可用的相同内容重复导入不再次复制。新导入的就地引用仅探测媒体信息及最多 192KiB 内容样本，不扫描整个视频；抽样标识不代表完整性校验，同路径重复引用可复用记录。
- 取消仅清除当前任务自身创建的临时文件。Windows 最终提交使用不覆盖模式的 `MoveFileExW`。不删除源素材或正式输出。断电遗留的未登记临时文件不会自动删除。
- 离线素材可通过播放器的“重新定位素材”选择文件；复制素材和旧版引用记录比较完整哈希，新版引用比较文件大小与内容样本（不能保证所有字节相同）。首版仅支持逐文件重定位。旧版引用记录仍保留原校验方式，需要快速导出时可重新建立拍摄记录；不会自动迁移正在运行的任务快照。
- 有比赛标记后禁止重排素材，避免悄悄改变内容；需要重排时建立新的拍摄记录。
- 首次进入桌面应用不会出现演示任务。验收时通过真实导入创建的记录明确命名为“合成测试 · 跨文件验收”。测试视频只在忽略的 `.test-data/` 与本机测试输出目录内。
