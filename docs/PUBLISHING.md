# B 站发布与恢复（v0.5.0）

## 使用

1. 保持原有导入、统一时间线和标局流程。在右侧勾选比赛，打开顶栏 **B 站发布**。
2. **用所选比赛创建草稿**：按保存的比赛顺序生成分 P；按源区间和预设的内容指纹查找成片，完整哈希核对后复用。缺少的才加入现有导出队列。这里使用编辑器当前导出预设，界面显示 H.264/H.265，不暗中改编码。
3. 或在发布面板 **导入既有成片**，显式选择已有 MP4；也可以勾选多个成片新建草稿。没有历史任务的文件不填造假的来源 session/match。
4. **扫码登录**，使用 B 站 App 扫描本机显示的二维码，再点击 **我已扫码，检查登录**。也可使用 **检查登录**检查系统凭据中的账号。分区从当前账号的接口读取；读取失败时不能确认投稿。
5. 编辑标题、简介、标签、分区、每 P 名称和顺序。可选择本地 JPEG/PNG 封面，或指定首 P 的时间取帧。保存草稿。
6. **上传 / 重试失败分 P** 只传文件，不提交稿件。可以关闭面板继续标局。同一次应用运行中，成功分 P 保留，失败重试不触发导出。
7. 核对账号、顺序、标题与公开可见性，点击 **确认投稿… → 确认提交稿件**。当前适配器只开放公开投稿，不伪装支持私密/定时等账号能力。
8. **查询平台状态**、**打开稿件**。已提交不等于已发布。查询只扫描最近至多五页，查不到或接口失败时保留此前状态，并显示查询错误。

二维码与网络接口没有云服务依赖。无需提供密码给开发者或模型。退出登录只删除本机系统凭据，平台上的其他登录/授权需自行在 B 站管理。

## 接入依据与验收边界

- 官方 [开放平台](https://open.bilibili.com/doc) 提供授权后稿件管理能力；本仓库没有已获准的开发者应用标识或授权配置，因此没有声称实现官方开放平台 OAuth。
- 第一版使用 B 站网页扫码、账号查询、UPOS 文件传输和网页投稿接口。协议参考当前维护的 [biliup/biliup 固定提交](https://github.com/biliup/biliup/tree/fbaf2046afd7688fa0ee9f8762734b449d00284c)，不依赖 master，也不调用会在上传后自动投稿的 CLI。许可见 [第三方声明](../THIRD_PARTY_NOTICES.md)。
- 2026-09-27 无账号探测：二维码生成返回 HTTP 200 / code 0，字段为 url、qrcode_key；分区接口在未登录时返回 code -101。没有扫描登录、传输用户视频或提交稿件。
- **未完成真实账号端到端验证**。扫码确认后的 Cookie、账号实际分区结构、上传线路、封面、投稿和审核查询目前由受控 HTTP 契约测试及协议审查覆盖，仍需用户授权的测试账号验收。接口变化、风控、账号权限限制会明确报错并停止，不绕过验证、不制造远端成功结果。
- UPOS 使用分块传输以限制内存，但没有宣称分块断点续传。失败文件从文件头重传；已成功文件不会因为另一 P 失败在同一运行中重传。
- 没有可靠的未投稿远端文件有效期查询契约。重启会把成功上传记录标为 **远端文件待核对**，需要明确选择重新上传待核对分 P。运行内复用的是最近的成功合并结果，不是远端永久有效保证；平台仍可能在最终投稿时拒绝它。
- 提交发生网络错误/超时或结果无标识时，保守标为 **结果待核实**，同草稿不能再发起提交。打开创作中心核对，输入 AV 号并勾选确认后才能关联，后端再向同账号稿件列表核对。没有用标题相同推断同一稿件。
- WebView 定位只验证加载/寻址状态与时间容差；不保证任意编码、长 GOP、VFR 的逐帧精确。实际 Pocket 3 长素材未在本次使用。

## 数据与崩溃恢复

SQLite 沿用现有 records 表与 v1 结构，增量增加 `artifact`（以及任务到成片的 `artifact_job` 关联）、`publication_draft`、`upload_part`、`publication` 类型，无删表/覆盖数据迁移。启动只恢复这些小型记录，不扫描所有视频。旧版不能理解新的投稿状态，建议不要降级运行开发中的数据库。

- 成片记录分开存储 `content_fingerprint`（源区间和预设）与 `file_sha256`（完整 MP4 哈希）。任务、拍摄、成片、投稿证据没有删除级联；清理已结束导出任务只删除 job。
- 成片提交前将验证结果和完整文件哈希写入输出目录的隐藏 `.任务ID.commit.json` 凭据，同步写入后用不覆盖提交移动正式文件。完成后在同一个 SQLite 事务中写 completed job 与 artifact。**文件系统操作和 SQLite 事务不是共同原子操作**。
- 若文件提交后数据库写入失败，暂停调度并保留待写状态。数据库恢复后继续队列可补交；重启后重试中断任务，先根据凭据完整哈希验证现有文件再恢复记录，不编码、不覆盖。凭据缺失或不匹配时明确拒绝，可显式导入既有成片。不要删除尚未恢复任务的 `.commit.json`。
- 旧 completed 任务按需迁移：只有选择相应比赛准备发布时，才核对旧输出的时长、编码、分辨率、首尾抽样解码与完整哈希，再保留旧任务来源快照。历史没有最终哈希，不能证明该文件在此次迁移前从未被同规格内容替换；旧任务的验证证据与本次身份建立时间明确分开。
- 素材重定位只改变旧任务执行位置，原始任务的素材内容身份、区间、顺序、预设不变。`verified-copy` 仍完整校验；v0.4 的 `sampled-reference` 仍只是有限抽样身份，不能解释为完整性保证。旧任务仅有抽样身份且路径已变更时拒绝复用历史任务，需用户核对素材并新建导出；无法事后补造移动前的完整哈希。
- 标记保存按 session 与修订串行确认，同一 session 的冗余待写版本可以合并。刷新保留未确认版本。正常退出等待确认；失败可重试、取消退出或明确放弃。未增加断电保护草稿日志，异常断电/强制杀进程仍可能丢失尚未确认的编辑。
- 领取和最终数据库写入必须成功，进度只用事件传输。job-update 带序号并节流；首次加载、回到前台、未知任务或序号缺口才拉取快照，没有每秒读取全库的轮询。

## 安全与尚待完成

凭据由 Rust 持有，保存在 Windows Credential Manager/macOS Keychain，数据库仅存账号引用。不读取浏览器 Cookie，不写 localStorage，不放命令行，不把平台原始认证错误响应或带参数 URL 写入日志。Linux 未配置安全凭据后端时明确禁用登录，避免 keyring 的模拟后端被当作安全存储。

HTTP 请求禁用重定向和自动重试，文件上传只接受 HTTPS/443 的 B 站上传域名。认证 Cookie 不发送给 UPOS CDN。原 WebView 的 CSP 和 asset scope 没有扩成任意来源或全盘。远端稿件只用系统浏览器打开。

仍待验收/完善：真实账号闭环、Windows 原生窗口关闭/更新联动、macOS 原生 UI/Keychain、Pocket 3 长素材；可靠的远端已上传文件过期查询、跨重启保留分块会话；更多状态协调与导入/导出队列 JSX 拆分，复制/导出前重复完整读取的进一步性能优化。当前已拆出保存协调、媒体定位协调和发布面板/服务，保留现有技术栈与界面风格。

## 封面备选

剪辑页暂停到喜欢的画面，点击“加入封面备选”。应用从对应原片位置生成独立 JPEG，原片只读，备选保存在本机应用数据目录。投稿页显示备选缩略图，点击后显示已选封面预览；选择随“保存草稿”持久保存。也可选择本地 JPEG/PNG，或按首 P 时间取帧。移除投稿封面不会删除备选。

取帧按媒体时间定位，不能保证所有编码/VFR 下与 WebView 所示画面逐帧一致。当前未增加裁剪、文字排版或备选删除功能。删除原片或拍摄记录不会删除已经保存的备选图。

备选使用现有 SQLite records 的 cover_candidate 类型，无破坏性表迁移。封面预览只允许已授权图片、已保存备选和稿件引用，单张读取上限 10 MiB；不扩大 CSP。发布页面能展示旧后端已授权的封面，但新增备选命令需启动新版后端。
